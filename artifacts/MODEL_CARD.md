# MODEL CARD — AI Personnel Stress & Welfare Risk (Core Risk Model)

## Intended use
Flags personnel for **voluntary welfare check-ins or human follow-up**, as one
input among several for a human welfare officer. It is a decision-support
tool, not a decision-maker.

## Explicitly out of scope / non-goals
- **Not a diagnostic tool.** It never outputs a clinical label (e.g.
  "depression", "PTSD"). Output is a risk band (Low/Moderate/High) and a
  calibrated probability only.
- **Not a disciplinary tool.** Output must never be used for punitive action.
- **Not a standalone suicide/self-harm predictor.** No module in this system
  infers self-harm risk as its own label. Any severe/urgent signal from the
  broader pipeline routes to immediate human welfare officer contact —
  never an automated message to the individual.
- **A human is always in the loop** before any welfare action is taken on the
  model's output.

## Training data
100% **synthetic**, generated by `data/generate_synthetic_dataset.py`. 1,500
synthetic personnel over 26 weeks, with deliberately injected missingness
(including MNAR-style non-response correlated with strain) and ~5% label
noise. This system has never had access to, and does not claim to reflect,
real personnel records.

## Model
LightGBM multiclass classifier (primary), calibrated with
`CalibratedClassifierCV` on a held-out-by-personnel calibration split. A
calibrated logistic regression serves as an explainable baseline and
contributes to the reported confidence interval via model-disagreement
spread.

## Evaluation
- Test macro-F1: **0.7318** vs. dummy
  (most-frequent-class) baseline: **0.2303**
  (beats baseline: True).
- CV macro-F1 (GroupKFold by personnel_id, 5 folds):
  0.6347 ± 0.0063.
- Per-class precision/recall/F1: see `reports/evaluation_metrics.json`.
- Brier scores (calibration quality) per class: see same file.
- Evaluated on a **temporal holdout** (last 5 weeks per person), never seen
  during training or calibration.

## Known limitations
- Synthetic data cannot capture the full complexity, rarity, or context of
  real personnel welfare situations. Real deployment requires revalidation
  on properly authorized, ethics-board-approved real data, plus ongoing
  drift monitoring (see roadmap note below).
- The model reflects patterns in a simulated latent "burnout propensity"
  construct designed by the build team, not any validated clinical construct.
- No fairness/bias audit was performed in this hackathon build (explicitly
  cut for time — see roadmap note).

## Roadmap (explicitly NOT built in this prototype, noted for future work)
- Fairness/bias audit across service branch, years of service, posting type.
- Drift monitoring in production (feature and prediction distribution shifts).
- Anomaly detection for data pipeline health.
- Federated-learning design, if data cannot be centralized across units.
- A contextual bandit for the recommender, trained on real post-intervention
  outcomes once the system has been deployed and outcomes data exists — the
  current recommender is intentionally rule-based and fully auditable
  instead.

## SIH-final upgrade addendum (v0.2.0-sih-final)

This model card was updated after the SIH-final feature upgrade. The two
items previously listed under "Roadmap (not built)" are now implemented:

- **Fairness/bias audit**: now implemented (`fairness_eval.py`). Evaluated
  across hardship-posting status, career-stage, and transfer-frequency
  subgroups (no protected characteristics are collected in this synthetic
  dataset by design). Overall macro-F1: 0.7318.
  Flags raised: no subgroup exceeded the fairness gap threshold. Full detail in
  `reports/fairness_report.json`.
- **Drift monitoring**: now implemented (`drift_monitor.py`), Population
  Stability Index per feature against the training distribution. Detection
  only — no automatic retraining. Current status vs. the held-out temporal
  test window: **significant_drift**
  (2 of 44
  features show significant drift). Full detail in `reports/drift_report.json`.

Also added in this upgrade, not present in the original build:
- A formal risk+trust **fusion with hard abstention**
  (`INSUFFICIENT_CONFIDENCE_HUMAN_VERIFICATION_REQUIRED`) when trust falls
  below a floor, instead of scoring on data too thin to trust.
- A **"What Changed" engine** giving officers a plain-language diff of which
  raw signals moved, not just a risk number.
- **Temporal SHAP**: which feature contributions grew as risk grew, not
  just which features matter at a single point in time.
- A **non-causal counterfactual/scenario simulator** for exploring
  hypothetical interventions with an officer.
- A **welfare-officer feedback store** (outcomes only, no causal claims) for
  future re-training.
- Every prediction now carries `model_version` + `feature_version` +
  timestamp (see `inference_pipeline.py`).

Feature version: `1.1.0`. Model version: `0.2.0-sih-final`.
